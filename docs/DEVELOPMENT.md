# Development

The repository contains one Rust Windows application and its optional Chrome extension.
`1.0.0` is the first published release; the earlier 3.x identifiers were development builds.

## Layout

- `src/`: platform-independent state machine, protocol, transcription and UI text.
- `src/win/`: Win32 windows, shortcuts, clipboard, recording and HTTP implementation.
- `assets/sounds/`: embedded PCM audio and its source/measurement notes.
- `extension/`: optional ChatGPT-tab integration; `config.js` is generated locally.
- `scripts/setup.ps1`: create installation credentials and synchronize the extension token.
- `scripts/package.ps1`: build a ZIP from an explicit file allowlist, without local settings.
- `tools/`: optional sound import/generation, image conversion and memory measurement tools.
- `docs/badge/`: UI images generated by the application's drawing code.

## Validate and package

Run in the repository root on Windows with Rust and Visual Studio C++ Build Tools:

```powershell
cargo test --locked
./scripts/package.ps1
```

The application and extension versions must match. Package outputs are in `dist/`.
Run `./scripts/setup.ps1` to configure a local checkout. Existing credentials and application
settings are preserved; a missing extension config is regenerated from the installation token.

CI runs the tests, checks extension JavaScript syntax and builds the Windows ZIP. The ZIP contains
the EXE, extension, setup/start scripts and quickstart. It contains no API key, bridge token, settings,
logs, source caches or development environment.

## Native checks

Normal tests do not record audio, call the transcription API or paste text into real windows.
Hardware/UI checks are opt-in; run the named check you intend to use:

```powershell
cargo test volume_slider_smoke -- --ignored --nocapture
cargo test sound_queue_plays_silent_waveforms_in_order -- --ignored
cargo test microphone_records_about_one_second -- --ignored
cargo test openai_rejects_invalid_key_over_https -- --ignored
```

The UI check uses an isolated hidden window without reserving the app port or global shortcuts.
It checks settings persistence, the four docking edges and stable GDI resource counts.

## Generate assets

Python is optional and used only while developing:

```powershell
$env:BADGE_SHOTS = "$PWD/build/badge"
cargo test badge_shots -- --ignored
python tools/rgba_to_png.py build/badge docs/badge
python tools/import_sound.py C:/path/listening.wav assets/sounds/listening.wav
```

`UPDATE_ICONS=1 cargo test icon` regenerates extension icons from `src/icon.rs`.
To regenerate the soft writing sound, install `tools/requirements.txt` into an optional development
environment, then run `python tools/make_processing_sound.py`. See the sound asset README for LUFS.

## Manual regression

- Test each dictation method with normal paste, paste + Enter, clipboard-only and cancellation.
- Start in one window and finish in another; verify the text reaches the finish-time target.
- In browser mode, test permission denial, tab loss and manual stopping inside ChatGPT.
- Change shortcuts and both status-window options; restart and confirm the settings persist.
- Dock on every edge, including corners and secondary monitors; reopen the status window.
- Change volume and sound pack; test quick state transitions and inspect `dikte.log` for failures.

To measure a built executable, exit the application first and run:

```powershell
./tools/measure.ps1 -Exe ./dist/ChatGPT-Dikte.exe
```

## Release

Update `Cargo.toml`, `Cargo.lock`, `extension/manifest.json`, the quickstart and changelog together.
After validation and CI, tag the release commit as `vX.Y.Z` and publish the ZIP and `SHA256SUMS.txt`.
Never replace old tags or rewrite the development history to renumber it.
